Title

Umami: Counting Visitors Without Cookies

Open-source, privacy-focused web analytics, presented by Group H.

Junliang Li

The analytics dilemma

Sites need traffic data, but cookie-based tracking comes with consent notices. Utz et al. (2019) found notices on over 60% of popular EU sites, and Nouwens et al. (2020) showed that hiding the first-page reject option raised consent by 22–23 percentage points. This sets our question: can we get useful analytics without relying on cookies?

Junliang Li

What is Umami?

An open-source platform for web and product analytics with a cookie-free tracker, available as managed Umami Cloud or as a self-hosted instance.

Junliang Li

What Umami measures

A traffic overview, visitor context (referrers, devices, browsers, approximate location) and custom events with properties for specific actions.

Junliang Li

UTM tracking and sharing

UTM reports compare traffic from tagged links (for example email versus social posts). Share URLs publish selected reports without giving out an admin account.

Xinyu Ye

How the parts connect

Browser → script.js sends a request to /api/send → the Next.js server filters bots and blocked IPs → PostgreSQL stores the event → the owner reads the dashboard. No cookie appears at any step.

Xinyu Ye

What Umami sees, and what it doesn't

The script sends page URL, title, referrer, screen size and language. The server adds browser, operating system, device and an approximate location. The IP address itself, cookies, and names or emails are not stored.

Xinyu Ye

Hashing: a fingerprint, not a cookie

The same inputs always give the same hash, so a morning and afternoon visit in October count as one visitor. In November the salt changes, the code changes, and the two months cannot be linked.

Xinyu Ye

The exact formulas

Session ID = hash(website ID + IP + user agent + monthly salt). Visit ID = hash(session ID + hourly salt). We checked both in Umami's source code.

Xinyu Ye

What this design costs

No identity is stored, but counts are approximate: changing network creates a "new" visitor, people sharing Wi-Fi and a browser may merge, and a hashed ID is still personal data under GDPR (EDPB, 2025). Precision versus privacy is a choice.

When (not) to use Umami

Use it for basic traffic and event reports without cookies, with control over where data is stored. Avoid it for deep advertising integration or person-level tracking across months.

Questions from the session

How does Umami track users who use a VPN?

Umami only sees the VPN server's IP address, not the user's real one. Because the session hash uses the IP, a user who stays on the same VPN server is still counted as one visitor; switching servers, or turning the VPN on and off, changes the IP and creates a new visitor. The location shown in the dashboard is the VPN server's country. Several VPN users sharing an exit IP with the same browser could also be merged into one visitor — the same precision trade-off described on slide 10.

Further questions we prepared for

Do UK sites still need a consent banner for analytics?

Umami sets no cookies. In addition, the ICO's 2026 guidance on the Data (Use and Access) Act 2025 allows storage and access purely for statistical analytics without consent, provided users are told and can object free of charge, and the results are aggregate with no profiling or advertising (ICO, 2026). In the UK, Umami's main advantage is therefore collecting less data rather than avoiding a banner.

Would you self-host it?

Our live demo used Umami Cloud for speed. Self-hosting with Docker Compose keeps the data on your own server, at the cost of handling updates, backups and data retention yourself. Our tutorial uses Umami Cloud.

How would you track real bookings rather than clicks?

Send a second event from the booking confirmation step, then build a funnel from viewing a stall, to clicking "Book", to a confirmed booking, to see where people drop off.
